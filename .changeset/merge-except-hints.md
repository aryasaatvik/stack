`stack merge --auto` gains `--except <branch-or-change>`: land every root in the stack except the named branch and its descendants — the "land everything except X" intent for a forked stack, the inverse of `--through`. It reuses the campaign machinery, so the excluded subtree is dropped from both the landing chain and the final repair pass's scope: those branches are never rebased or pushed (a landed parent still retargets them to trunk pre-merge so their requests survive; their history waits for their own campaign). `--except` requires `--auto`, is mutually exclusive with `--through`, errors on an unknown branch, and errors when excluding the only root leaves nothing to merge. Like `--through`, an `--except` campaign persists in `.git/stack/campaign.json` and resumes with `stack merge --continue`. The `--through` help now documents its sibling semantics precisely: `--through` lands only the roots on the chain to the target; sibling subtrees are never merged by it and, under lazy repair, are not rebased until the final pass.

Replay-conflict failures now print the full surgical manual-recovery recipe instead of a one-line hint: `git fetch origin`, then `git rebase --onto <new-parent> <backup-ref-just-created> <branch>` (the run's backup ref is the pre-rewrite parent tip / range base, so only the branch's own commits replay instead of the wide merge-base range that conflicted), resolve, `git push --force-with-lease origin <branch>`, then `stack merge --continue` (campaign) or `stack sync --apply <branch>`. The hint warns to rebase against freshly fetched refs, never a stale local trunk — a rebase built on a stale trunk succeeds locally but breaks a merge one or two PRs later. The shipped skill documents `--except`, the `--through` sibling semantics, a dedicated manual-recovery section with the backup-ref recipe, and that pre-PR children join the topology via `stack track <branch>` rather than a draft anchor PR.
